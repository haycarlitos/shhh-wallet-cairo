# Upstream Garaga PR: `bls_calldata_builder` for arbitrary BLS messages

> **Goal:** add a generic `bls_calldata_builder` to the Garaga npm
> bundle so wallet SDKs can build BLS verification calldata for any
> 32-byte message digest, not only drand round numbers. Removes the
> Python-only constraint that currently gates the Shhh V8
> `Bls12_381MinSigVerifier` JS-side signing flow.

## Problem

Garaga (npm) currently exposes BLS-related calldata builders only
through `drand_calldata_builder` / `getDrandCallData`. Both are
hardcoded to drand's round-numbered message format:

```text
message     = sha256(round_be_8B)        // 8-byte round → 32-byte digest
ciphersuite = BLS_SIG_BLS12381G1_XMD:SHA-256_SSWU_RO_NUL_+
chain pk    = drand quicknet's hardcoded G2 pubkey
```

That serves the drand beacon, but it's the only BLS path the npm
package exposes. Every other BLS use case (validator multisigs, DAO
governance keys, application backend signers, the Shhh V8 BLS signer
kind) needs to bind a custom 32-byte digest to a per-account G2
pubkey. There is no JS-facing entry point for that today.

The Python `garaga` package already has every primitive needed:

- `garaga.starknet.tests_and_calldata_generators.map_to_curve.build_hash_to_curve_hint(message: bytes)`
  → `HashToCurveHint` for any 32-byte digest.
- `garaga.starknet.tests_and_calldata_generators.mpcheck.MPCheckCalldataBuilder`
  → `MPCheckHintBLS12_381` + precomputed `G2Line<u384>` array for
    arbitrary `[G1G2Pair]` inputs.

The Rust core (`tools/garaga_rs/src/calldata/drand_calldata.rs`)
already does all the heavy lifting; it just gates on the
drand-specific `RandomnessBeacon` shape. Lifting that gate is a
small change.

## Concrete consumer

Shhh Wallet V8 ships `Bls12_381MinSigVerifier`
([haycarlitos/shhh-wallet-cairo `v8-robust`](https://github.com/haycarlitos/shhh-wallet-cairo/tree/v8-robust),
commit `0b07769`, 9/9 tests passing). The on-chain class works today
using fixtures generated by `scripts/py/gen_bls_fixture.py` (Python
`garaga`). Once `bls_calldata_builder` lands in the npm bundle, that
generator can be ported to TypeScript so end users sign in the
browser without a Python sidecar.

## Proposed Rust API (mirrors `drand_calldata_builder`)

```rust
// tools/garaga_rs/src/calldata/bls_calldata.rs
//
// Inputs (BigUint flat array, matching drand_calldata_builder shape):
//   values[0]: message_hash            — 32-byte BE digest
//   values[1]: signature_g1_compressed — 48-byte BLS-compressed G1
//   values[2]: pubkey_g2_compressed    — 96-byte BLS-compressed G2
//
// Output: full calldata felt vector
//   1. signature_g1: G1Point Serde       (8 felts)
//   2. h2c_hint:     HashToCurveHint     (12 felts)
//   3. lines_len:    u32 (= 136)         (1 felt)
//   4. lines:        G2Line<u384> × 136  (2176 felts)
//   5. mpcheck_hint: MPCheckHintBLS12_381 (~2079 felts)
//
// DST: BLS_SIG_BLS12381G1_XMD:SHA-256_SSWU_RO_NUL_+ (drand quicknet
//      ciphersuite, the only one Garaga's
//      hash_to_curve_bls12_381 currently supports).
pub fn bls_calldata_builder(values: &[BigUint]) -> Result<Vec<BigUint>, String>;
```

Implementation cribs from `drand_calldata_builder`
(`tools/garaga_rs/src/calldata/drand_calldata.rs`), with these
deltas:

1. Skip the chain-info lookup — the caller supplies their own G2
   pubkey instead of resolving it from `DrandNetwork::Quicknet`.
2. Skip the round-number → message digest derivation — the caller
   supplies their own 32-byte digest.
3. Reuse `mpc_calldata::build_calldata_for_pairing_check` for pairs
   `[(sig, G2_GEN), (H(m), -pubkey_g2)]` with `n_fixed_g2 = 2`.

A `bls_calldata_builder_g2sigs` (min-pubkey-size, Eth-validator
style) is a follow-up that waits on
`hash_to_curve_g2_bls12_381` landing in `garaga::apps`.

## What the PR has to ship (Garaga's contributor invariants)

Per `CLAUDE.md` at the repo root:

- **Rust path**: `tools/garaga_rs/src/calldata/bls_calldata.rs` +
  `pub use` from `tools/garaga_rs/src/calldata/mod.rs`.
- **Python parity**: a Python builder that returns the same
  `Vec<BigUint>` byte-for-byte, plus a pytest that asserts
  `calldata_py == calldata_rs` over a deterministic fixture.
  (Existing `MPCheckCalldataBuilder` covers most of this; the
  wrapper lives next to `drand` in `hydra/garaga/drand/` or a new
  `hydra/garaga/bls/`.)
- **WASM binding**: `#[wasm_bindgen]` export in
  `tools/garaga_rs/src/wasm_bindings.rs`. After the Rust change,
  run `make wasm` (Docker-based) and commit regenerated files in
  `tools/npm/garaga_ts/src/wasm/pkg/`. CI fails if out of sync.
- **TypeScript wrapper**: typed function in
  `tools/npm/garaga_ts/src/node/api.ts`, plus a Jest test in the
  same package, plus coverage in all four integration suites
  (Node CJS, Node ESM, Webpack, React) under
  `tools/npm/garaga_ts/integration_tests/`.
- **E2E test**: a starknet-devnet test under `tests/` that deploys
  a 2P_2F BLS verifier, generates calldata with the new builder,
  invokes `verify`, and asserts via `wait_for_acceptance()`.
- **Lint + format**: `cargo clippy --workspace`, `make fmt`,
  `cargo test -p garaga_rs`, `snforge test -p garaga`.

## Test vector

Pinned to the same fixture the Shhh V8 verifier ships
(`scripts/py/gen_bls_fixture.py` in haycarlitos/shhh-wallet-cairo):

```text
message_hash = 0x05bcd634ce46c7234bd7a4b0959c3c5edeed7f569dcfb7b33e23d7e2197a2a2f
sk           = 0x12345678
pubkey       = sk · G2_GEN
signature    = sk · hash_to_curve_g1(message_hash)
expected envelope length = 4276 felts
```

The pytest parity check asserts `bls_calldata_builder_py(values) ==
bls_calldata_builder_rs(values)` element-wise on this vector. A
single round-trip Cairo test (deploy a thin BLS verifier on devnet,
invoke `verify`, expect Ok) is enough proof that the JS path
produces the same data the existing Cairo primitives consume.

## Process

Open a Feature Request issue first (Garaga's
`02_FEATURE_REQUEST.md` template, `feat:` title prefix) so the
maintainers can shape scope before code. Then fork, build the five
deliverables above, and open the PR linking back to the issue.

PR title (matching their PR template style): summary in the title,
no `feat:` prefix.

PR template fields to fill:

- Type: Feature
- Issue Number: <link to feature-request issue>
- Current behavior: only `drand_calldata_builder` exists; locked to
  drand round messages and quicknet pubkey.
- New behavior: `bls_calldata_builder(values)` accepts arbitrary
  32-byte message + per-call G2 pubkey + G1 signature; emits the
  same calldata shape Garaga's existing Cairo primitives consume.
- Breaking change: No.
- Other: link this doc + the Shhh V8 verifier + pinned test vector.

## What we ship while waiting

The Shhh V8 verifier doesn't block on this PR. We use the Python
`garaga` package today and `scripts/py/gen_bls_fixture.py` for
offline fixture generation (see
`tests/signer_bls12_381_fixture.cairo`). The Cairo verifier class
hash is determined by the Cairo source alone — when this upstream
PR lands, the fixture generator can be ported from Python to TS
without changing the on-chain class.
