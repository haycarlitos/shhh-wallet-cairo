# SDK parity fixtures

Cross-language parity fixtures captured from a third-party TypeScript SDK that
consumes V8.4 `ShhhAccount`. The point of these fixtures is drift detection:
if the Cairo side or any reference SDK ever computes a different
`owner_commitment`, address salt, OE message hash, or envelope encoding for
the deterministic inputs pinned here, parity has broken.

## What's pinned

For each Cycle-1 signer kind (STARK, ED25519, EIP191_SECP256K1,
WEBAUTHN_P256), the fixture records:

- `testPrivateKey`: the deterministic 32-byte seed shared across all kinds
  (`0x01..0x20`).
- `primaryKindFelt`: the ASCII felt encoding of the kind label
  (e.g. `"STARK"` becomes `0x535441524b`).
- `verifierClassHash`: the V8.4-declared verifier class hash for the kind.
- `computed.walletAddress`: the counterfactual address derived from the
  primary kind + verifier + pubkey + label.
- `computed.addressSalt`: the salt used when computing the address.
- `computed.constructorCalldata`: the calldata passed to the deployer.
- `computed.oeMessageHash`: the SNIP-12 hash of an OE with empty calls
  (chosen as the cheapest no-op for mainnet verification).
- `computed.envelope`: the V2_SNIP12 envelope produced by the SDK,
  including kind tag, owner id, and per-kind signature payload.

OE nonces and time windows are timestamp-derived and explicitly NOT
parity-relevant; the assertion is that the envelope verifies against the
included pubkey for whatever OE message hash was produced.

## Provenance

The receipt was generated by a smoke runner that deploys one fresh SHHH
wallet per kind on Starknet mainnet and submits an empty-calls OE through a
sponsored paymaster. The `mainnetTxHash` field on each fixture is the
`deploy_and_invoke` transaction; inspecting it via any explorer confirms the
verifier dispatch resolved to the expected class hash and the OE executed.

Block range: 10059021 to 10059037, 2026-05-22.

## How to use

Cairo-side tests can read this JSON and assert that:

1. Recomputing `owner_commitment(primaryKindFelt, pubkey_from_test_key)`
   produces the same value embedded in `envelope[1]`.
2. Recomputing the address from the constructor calldata produces
   `computed.walletAddress`.
3. The on-chain transaction at `mainnetTxHash` deployed to that address.

A drift in any of these three checks across releases is a parity break and
should fail CI before any class redeclaration ships.

## Adding kinds

Cycle 2 / Wave B kinds (JWT_ES256, JWT_ES256_APPLE_SUB, P-256 raw, etc.)
should be appended to `cycle1-fixtures.json` (rename if a new cycle starts)
with the same shape. Schema is versioned at `meta.schemaVersion`.
